# 开发与本地维护

本文面向开发者和 Agent，说明当前源码的构建与维护方式。使用方法见 [README](../README.md)，测试命令与验证边界见 [TESTING](TESTING.md)，正式版本变化见 [CHANGELOG](../CHANGELOG.md)。

## 构建环境与命令

在 Windows 上使用系统自带的 .NET Framework C# 编译器。脚本使用 `%WINDIR%\Microsoft.NET\Framework64\v4.0.30319\csc.exe`，目标为 .NET Framework 4.8、x64，界面使用 WPF。CI 使用 Windows Server 2022 和 `pwsh`；本地应使用能执行脚本的 PowerShell 环境。程序用户无需安装 PowerShell 7、Node.js 或 Python。

以下命令均从仓库根目录执行：

```powershell
.\scripts\Build.ps1
```

默认输出 `WuwaTappoHelper.exe`、`WuwaTappoHelper.exe.config` 和用于编译的 `Version.cs`。需要同时编译并运行全部原生检查时使用 `-Test`。日常通过 `./scripts/Test.ps1 -Suite Worker` 等入口按功能检查，完整命令见 [TESTING](TESTING.md)。桥接脚本测试使用 Node.js；README 动态预览额外需要 FFmpeg，二者均不是助手运行依赖。

## 版本与输出目录

[Build.ps1](../scripts/Build.ps1) 的规则如下：

| 情况 | 程序版本与输出 |
| --- | --- |
| 默认本地开发构建 | 找当前提交可达的最近正式版本标签（排除预发布标签），补丁号加一，再加独立构建序号；输出 `build/X.Y.Z.N/`，显示 `X.Y.Z.N-dev`。 |
| `-Version X.Y.Z` 或 `-Version vX.Y.Z` | 构建指定三位版本，不附加开发序号或 `-dev`；本地默认输出 `build/X.Y.Z/`。这只生成本地文件，不创建 Git 标签或 Release。 |
| 测试版构建 | `-Version X.Y.Z-beta.N` 保留预发布标识，程序集使用三位基础版本。 |
| CI 标签构建 | 使用 `GITHUB_REF_NAME` 对应的正式或测试版本，不附加 `-dev`。 |
| CI 非标签构建 | 最近可达标签的下一补丁版本加 `-dev`，不附加本地序号。 |
| `-OutputDirectory` | 仅显式指定 `-Version` 或在 CI 中可覆盖输出位置；默认本地构建固定使用数字目录。CI 默认输出 `build/`，供后续打包使用。 |

例如最近标签为 `v0.1.4`，本地依次生成 `build/0.1.5.1/`、`build/0.1.5.2/`。末位取 `build/` 中现有同一前三位版本目录的最大序号加一，不推进正式发布版本号；删除所有相应目录后序号可能重新从 1 开始。版本标签不可用时，基础值回退为 `0.0.0`，再按开发构建规则计算。

```powershell
# 显式构建一个三位版本，不发布
.\scripts\Build.ps1 -Version 0.1.5

# 需要隔离输出时，仍使用数字版本目录；序号应按现有目录选择
.\scripts\Build.ps1 -Version 0.1.5 -OutputDirectory .\build\0.1.5.2
```

四位本地版本写入程序集版本，完整的 `-dev` 标识写入信息版本；[更新检查](../src/Updates.cs)以程序集前三位比较正式版本。不要把本地末位序号当作新的 Release 版本。

清理旧构建前检查运行中的 exe、配置及 `runtime/`。不要覆盖正在运行的程序，不要把账号操作记录当作构建垃圾删除；保留正在运行的版本，另建数字目录验证。构建脚本本身不负责清理旧版。

## 产品行为与安全要求

**运行环境。** 支持 Windows 10 22H2 和 Windows 11、x64、.NET Framework 4.8。引入 API、WPF/XAML 属性或依赖时核对最低支持版本，界面改动验证 XAML 解析和窗口创建。提高最低要求须先确认，并同步用户说明。

**连接与启动。** 核实连接目标的身份及其与所选桌宠的归属关系。进程名、端口号和页面响应只能提供候选线索。只有显式启动流程可以启动桌宠，普通断线重连只连接现有进程。修改归属校验时，核对已验证的合法宿主关系和应拒绝的跨实例连接。

**写入与确认。** 按实例和账号隔离操作。写入前核实所需能力，持久化发送意图。超时、页面重载、回执丢失或账号变化时保留待确认记录，恢复只核对原操作。重复保存、重连和人工确认均不得造成重复补数或领取。

**回执与最终结果。** 收到成功回执后可以显示“已领取 · 确认中”，保留对应回执时间。最终核验应将扣数、槽位冷却和奖励变化对应到原操作；固定双箱分别记录两笔发送意图及回执。

**等待与数据保护。** 遵守服务器强制等待及用户停止意图，未结束的写入不得重叠。退出和更新保留实例配置、历史与待确认记录。凭据留在受控链路内，诊断只记录必要的脱敏信息。

## 实例与本机数据

程序以 exe 所在目录保存默认窗口的配置和 `runtime/`。额外实例以规范化程序路径的 SHA-256 为标识，配置及运行目录放在 `runtime/instances/<id>/`；`--instance <id>` 在面板和提权后台间传递。每个实例保留独立的文件锁、控制命令和待确认记录，新增实例不能在原窗口更换绑定路径。默认窗口有待确认操作时禁止换路径。

窗口按数据目录互斥；后台另按当前 Windows 用户和桌宠路径持有命名互斥量，阻止不同助手目录同时接管同一桌宠。推荐始终使用同一份助手，以保留连续的恢复记录。

同一实例的原生后台在整个运行期间独占 `worker.guard`。锁已被占用时阻止重复启动，即使此时无法查询进程身份。向原生后台发送控制命令还需核对 `status.json` 与 `lock.json` 中的实例、会话、PID 和进程创建时间。身份记录不完整或已确认 PID 被复用时，面板和 `--control` 均拒绝发送；原生后台只执行目标会话与自身匹配的命令。旧版 Node 后台沿用原有的 PID 兼容检查。

| 文件 | 用途 |
| --- | --- |
| `config.local.json` | 桌宠路径。 |
| `runtime/preferences.json` | 所选模式。 |
| `runtime/events.jsonl` | 追加式活动日志，面板显示最近三条，暂无自动轮转。 |
| `runtime/status.json`、`runtime/control.json` | 后台状态、接口宝箱时间和面板控制命令。 |
| `runtime/pending.json`、`runtime/history/` | 未确认操作，以及手动确认后归档的原记录、摘要和处理说明。 |
| `runtime/worker.guard`、`runtime/lock.json` | 原生后台全程独占 `worker.guard`，取得锁后才可替换该实例遗留的原生运行标记。旧版 Node 标记仍检查 PID。 |
| `runtime/panel-lifecycle.log`、`runtime/panel-launcher-error.log`、`runtime/launcher-status.json` | 窗口生命周期及启动诊断。 |
| `runtime/debug-startup-session.json` | 调试启动方式、进程及连接就绪结果。 |

## 启动与连接排查

面板显示“重新连接”时，用同一构建、实例和会话的记录区分首次连接失败、连接后断开、后台退出、界面状态过期及账号接口失败。旧包正常而新包异常时，核对实际产物，定位改变相关路径的提交及首个包含它的发布版本，再与现场症状比对。由 `explorer.exe` 启动 WebView2、参数无法提供调试端口这两类场景均有[兼容性记录](TESTING.md#连接版本兼容与多实例)。

[Platform.cs](../src/Platform.cs) 使用 WebView2 支持的宿主命令行参数 `--edge-webview-switches="--remote-debugging-address=127.0.0.1 --remote-debugging-port=<port>"` 启动桌宠；每次启动分配可用端口，不修改系统注册表或助手自身环境。连接前通过进程路径、进程树和 TCP 监听进程核实端口归属；歧义或无法核实时拒绝连接。停止并恢复只等待所选桌宠退出，不受另一服的监听端口影响。参数随桌宠进程保留，使主窗口与辅助面板使用一致的 WebView2 环境选项，避免启动后撤回参数导致 `0x8007139F`。完整保留子进程继承的 `WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS`，不丢弃用户的代理、GPU 等设置；宿主命令行参数由 WebView2 最后处理，覆盖冲突的调试地址和端口。普通恢复启动不添加助手的调试命令行参数，仍保留用户环境设置。仅设置环境变量的方案已在真实桌宠中观察到调试端口未启用，不再采用。

通过系统读取的 WebView2 启动参数补全宿主关系：浏览器必须启用嵌入模式、宿主名为 `WuwaTappo.exe`，且唯一的 `--mojo-named-platform-channel-pipe` 参数以所选桌宠 PID 开头。这覆盖 WebView2 由 `explorer.exe` 启动、并非桌宠子进程的情况；只接受实际程序名为 `msedgewebview2.exe` 的浏览器根进程，不接受 renderer 等辅助进程作为宿主根。程序文件还必须具有有效的 Microsoft Authenticode 签名及 WebView2 产品信息，校验使用本机证书缓存，不发起网络请求。

优先从所选桌宠或其已核实 WebView2 参数中取得候选调试端口，再以新建回环连接的服务端 TCP 记录核实归属。参数无法提供端口时，从该进程树的 IPv4 回环监听记录收集候选；每个候选必须通过 TCP 归属、CDP 版本响应、`tauri.localhost` 页面与 `main` 窗口标签验证，随后再次核实 TCP 归属，且只能有一个候选通过。参数端口存在歧义时不使用此回退；HTTP 探测禁止重定向。一次探测期间持有所选桌宠和宿主浏览器的进程句柄，检查存活状态及创建时间，拒绝早于当前桌宠启动的浏览器，避免退出后的 PID 复用被误认；读取 TCP 记录后重新核实进程存活状态并刷新进程树。宿主参数不能替代 TCP 归属证据，其他桌宠、非回环监听、歧义或无法核实的归属仍拒绝连接。导出诊断以固定分类记录参数端口不可用、参数歧义、监听候选验证失败或歧义及归属失败，不记录原始命令行。

## 账号操作与恢复

连接、版本变化及写入前检查接口能力。只有完整校验成功后才替换映射，分别处理资源未就绪和接口不兼容。账号标识使用包含环境信息的摘要，诊断日志不记录原始账号标识或凭据。

发送前将意图写入 `pending.json`。单箱恢复匹配操作编号、账号摘要及原 store，再核对扣数、目标槽位冷却、另一槽位未变及奖励。固定双箱在同一个待确认文件中保存两笔独立发送意图及回执。左箱成功回执落盘且本地扣数已安全应用后，再根据同账号余额和槽位预检提交右箱。恢复只读取账户和背包，核对总扣数、两个槽位及每种奖励的份数。

当前[领取链路](../src/Bridge/claim.js)默认使用账号查询的累计值。查询总数落后时，可使用本会话中同账号的原版成功上报值，前提是它仍等于桌宠本地记账总数。单箱和双箱均以账号查询计算余额，最终核验要求查询累计达到实际发送值。成功后更新本地消费，并在回执有效时提前同步对应槽位的冷却，保留本地增量及桌宠自身保存与上报流程。

桌宠请求层会自动显示业务错误。助手领取使用校验过的同一接口和参数独立发出请求，仅对冷却拒绝 `70006` 跳过提示，仍核对拒绝结果并等待。凭据续期沿用原生背包预检，凭据仅留在页面；桌宠的全局通知和手动领取入口保持原有行为。

停止运行后重新启动，可跳过普通退避并立即重新检查；服务器限流与 `Retry-After` 仍然有效，手动停止须由用户恢复。“确认并继续”校验文件摘要并归档原记录，不重放原操作。

## 自动运行与更新

面板与托盘共用“启动后台／停止运行”：停止运行只暂停自动操作，保留桌宠；用户主动启动时会检查桌宠，已退出时重新打开。自动断线重连不启动桌宠，手动启动也不跳过服务器要求的查询间隔。存在待确认记录时阻止恢复操作。启动诊断保存失败会停止后台。“退出助手”只断开连接，调试入口保留至桌宠退出。所有停止流程保留待确认记录；升级保留 `config.local.json` 和整个 `runtime/`，不为测试删除实际账号的待确认记录。

`Preference.autoRun` 默认 false，与模式参数一起按实例保存。真实面板首次显示时仅尝试一次，复用已有启动/恢复入口；已运行、状态过期、待确认记录或路径无效时不启动，不自动弹出路径选择窗口。托盘恢复和切换开关不会触发运行，启动仍沿用现有提权流程。预览不执行自动运行。

更新包沿用 Release 的 `WuwaTappoHelper-win-x64.zip`，下载前验证附件地址、大小及 SHA-256 摘要，解压只接受现有五个分发文件并核对程序集版本。文件暂存于 `runtime/updates/<id>/`。点击“重启并更新”后，由临时复制的助手通过 `--apply-update` 入口协调同目录窗口和后台退出；后台在操作边界停止，不强制结束进程、不恢复或重启桌宠，也不清除待确认记录。所有助手进程退出后再替换分发文件，失败时回滚；成功后重开原窗口，并按该实例的“自动运行”设置决定是否启动后台。已完成的暂存目录在后续启动时清理，失败时保留诊断及回滚文件。

## 面板交互与用户文案

**已约定的键盘行为。** 普通和 Mini 面板共用按钮焦点提示。主动按 Tab 或 Shift+Tab 后，获得键盘焦点的按钮显示描边；鼠标点击面板后恢复鼠标样式。单按 Alt 或使用 Alt+Tab 不额外显示描边，切回窗口时由系统恢复原有焦点。控件按键及系统窗口切换沿用 WPF 和 Windows 的正常行为。

**控件与提示的设计。** 选择图标、标签和悬停提示时，考虑使用者能否辨认动作、区分相邻操作、理解必要后果。可见内容已表达清楚时，通常省去重复提示；图标含义容易混淆、文本被截断或操作影响尚未展示时，提示可以补足信息。图形辨识度、悬停提示和读屏名称分别解决不同的使用问题。

**用户文案。** 按钮、提示、对话框、README 和更新说明对同一动作使用一致名称。用自然、简洁的语言说明用户能做什么、发生了什么，以及需要怎样处理。限制与风险说明应对应实际使用影响。实现原因、测试过程和证据边界写入面向维护者的材料。

## CI、分发与发布

[build.yml](../.github/workflows/build.yml) 在 `main` 推送、`v*` 标签推送及手动触发时运行原生和桥接全量检查，随后暂存分发文件、执行包内 `--check` 并生成便携 ZIP。

当前打包清单严格包含五个文件：exe、exe.config、README.md、config.example.json、LICENSE。打包阶段执行 `--check`，要求文件数为 5、总大小不超过 5 MiB。仓库与分发包不包含本机配置、运行记录、桌宠安装文件或账号数据；分发包也不附带 `docs/` 和 README 预览图片，相关文档需在仓库中查看。

通过检查的 ZIP 上传到 **Artifacts**，保留 30 天；推送版本标签时进一步创建 **GitHub Release**。

### 发布步骤

取得涵盖发布的授权后，按以下步骤执行。

1. 在 [CHANGELOG](../CHANGELOG.md) 添加 `## [X.Y.Z] - YYYY-MM-DD` 小节（测试版为 `X.Y.Z-beta.N`），记录本次版本变化。
2. 对发布候选完成[全量回归与关键场景验证](TESTING.md#从任务目标选择验证)，在验证报告中明确尚未实测的边界；影响用户使用或升级的限制仍需写入更新说明。
3. 推送标签前，按工作流的提取规则核对最终 Release notes，确保内容准确、简洁且与待发布版本一致。
4. 经授权推送 `vX.Y.Z` 或 `vX.Y.Z-beta.N` 标签，由工作流构建、打包和发布。测试版发布为 prerelease，不标记为 latest。工作流将对应小节填入 Release notes；标签格式不符，或记录缺失、为空、重复时发布失败。

## README 动态预览

仅在需要更新预览时手动执行，正常构建和发布不会自动生成图片。Windows 开发环境需要 FFmpeg：

```powershell
.\scripts\Generate-ReadmePreview.ps1
# FFmpeg 不在 PATH 时：
.\scripts\Generate-ReadmePreview.ps1 -FFmpeg 'C:\tools\ffmpeg\bin\ffmpeg.exe'
```

[Generate-ReadmePreview.ps1](../scripts/Generate-ReadmePreview.ps1) 单独构建到 `build/readme-preview/`，通过 `--render-preview 帧输出目录` 生成 11 张模拟 PNG，再编码为 11 秒无限循环的 APNG，输出到 [docs/images/readme-motion.png](images/readme-motion.png)。中间帧位于 `build/readme-preview/frames/`。

渲染复用真实 `Panel.xaml` 和 `Panel.Render()`，不另绘近似界面。程序在创建真实运行目录前分流预览入口，跳过桌宠查找、连接、托盘及更新检查；模拟状态写入独立临时目录，结束后清理该临时目录，不读取或修改真实 `runtime/`。预览展示不是实际账号操作的测试证据。
