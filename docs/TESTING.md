# 测试与验证

使用方法见 [README](../README.md)，构建和内部约束见 [DEVELOPMENT](DEVELOPMENT.md)。本页介绍自动测试、真实桌宠只读探测和真实账号操作的验证范围。

## 按改动范围检查

从仓库根目录执行；原生测试需要 Windows/.NET Framework，桥接测试需要 Node.js，环境见[开发文档](DEVELOPMENT.md)。日常修改只运行受影响的组，跨层修改运行相关各组；提交或发布前运行一次全量，不必在每次小改后重复全量。

| 改动范围 | 命令 | 覆盖 |
| --- | --- | --- |
| 策略、Worker、连接、恢复、状态文件、能力校验 | `./scripts/Test.ps1 -Suite Worker` | 策略边界、待确认记录、服务器确认、退避与手动重试、断线恢复、版本映射。 |
| WPF 面板、托盘、关闭、反馈及更新交互 | `./scripts/Test.ps1 -Suite Panel` | 布局、按钮指令、提示优先级、暂停、隐藏／唤起／退出及更新交互；会打开隔离测试窗口。 |
| 多实例、启动参数、WebSocket、更新请求 | `./scripts/Test.ps1 -Suite Platform` | 实例数据隔离、跨进程互斥、端口归属、WebView2 宿主绑定与跨桌宠隔离、拒绝未签名的同名浏览器、旧浏览器创建时间和退出进程校验、调试端口优先于其他监听端口、子进程参数保留、回环连接释放、版本比较、HTTP 错误和取消；更新包校验、解压边界、替换回滚及配置和待确认记录保留。 |
| 所有桥接脚本 | `./scripts/Test.ps1 -Suite Bridge` | 资源发现、补数、领取及状态查询。 |
| 单个桥接脚本 | `./scripts/Test.ps1 -Suite Boost` | 可选 `Discovery`、`Boost`、`Claim`、`Pair`、`State`。 |
| 全量回归 | `./scripts/Test.ps1` | 全部原生与桥接测试。 |

例如改动 `boost.js` 只跑 `Boost`；同时改动 Worker 的补数处理，再跑 `Worker`。修改共享 `state.js` 或桥接能力契约时跑 `Bridge` 和 `Worker`；共享数据模型或跨模块重构跑全量。纯文档修改只核对内容和链接，无需构建、探测真实桌宠或生成预览。

`./scripts/Build.ps1 -Test` 运行全部原生测试，CI 保持全量检查。原生测试使用临时文件、模拟客户端、WPF 窗口与子进程和回环 WebSocket；JS 使用模拟模块、store、时钟及请求。测试与真实账号、桌宠及系统启动配置隔离。本地检查和远程 CI 分别报告结果。

关键回归验证补数保存串行执行、退避后继续保存，以及真实输入与新旧上报竞争的处理；领取以消费和奖励背包增量共同确认，查询失败或迟到时保持未确认，刷新失败时保留原领取操作。

`Worker` 组还包含诊断包验收：隔离子进程突然退出、PID 创建时间不匹配、未结束调用与独立心跳、状态写入失败、暂停未应答、模拟休眠通知与心跳间隔、旧会话/目录拒绝、重开后历史关联、凭据/路径排除及大小与轮转限制。测试直接检查导出 ZIP 中的证据。休眠通知采用模拟输入；真实系统休眠、磁盘整体失效和操作系统冻结仍属于真实环境验证边界。

`Panel` 组还验证按操作区分的超时提示、身份未知与确认退出的区别、旧数值及时间标注、独立累计统计、迟到确认后的提示清理，以及这些状态在最小窗口中的展示。启动提权文案使用纯函数夹具，不启动真实后台或管理员窗口。

## 程序检查入口

仅检查嵌入资源，不连接桌宠：

```powershell
& .\build\0.1.5.1\WuwaTappoHelper.exe --check
```

对已运行且可连接的桌宠进行只读探测：

```powershell
$probePath=Join-Path (Get-Location) 'build\0.1.5.1\probe.json'
& .\build\0.1.5.1\WuwaTappoHelper.exe --probe $probePath
```

以上路径仅为示例，请换成待测构建及本机输出绝对路径。探测前须配置所选桌宠路径；探测新增实例时，在参数末尾附加 `--instance <id>`，标识取自 `runtime/instances/` 中对应目录名。`--probe` 会创建助手目录下的 `runtime/`，并写入指定探测文件；失败也可能写启动诊断。它读取真实桌宠接口、校验本地状态和服务器宝箱时间，不执行补数、领取或桌宠重启，也不会为普通启动的桌宠自动开启调试会话。`--check` 或 `--probe` 成功均不能替代真实领取验证。

界面预览使用模拟数据，生成方式见[开发文档](DEVELOPMENT.md)。

### 仍需真实验证

以下场景尚待真实环境验证：

- 独立契约工具已验证国服桌宠 1.0.5 在收到左箱成功回执、账号查询仍显示旧扣数和旧冷却时，于 1.915 秒后提交右箱并成功。两份奖励各增加一份，随后的只读查询确认总扣数增加 2,000 和两个槽位分别进入冷却。回执落盘、合并查询及中断不重发有隔离覆盖。
- 双服同时托管时，分别暂停／恢复、断线重连和停止桌宠的完整流程，以及互不干扰的长期运行。
- 首次管理员启动、取消权限提示或启动失败后的完整恢复。
- 真实断线重连、其他原因导致的首次连接失败与恢复；补数或领取请求途中断线、慢响应、服务器错误、限流及保存失败后的恢复。
- 旧计数上报覆盖补数，以及观察超时后迟到回执的真实时序。
- 桌宠运行期间更新、页面重载或重启，包含能力重新发现、回执丢失和未确认记录的处理。
- 换账号、手动领取或其他计数变化时，确保不会错误确认原操作、重复补数或重复领取。
- 锁屏后持续运行、休眠期间停止执行及唤醒后的完整恢复。
- 开机自启与自动运行的完整登录流程，包括管理员确认被取消、首次发现桌宠路径和待确认记录拦截。

真实操作会影响账号次数与宝箱状态，应在获得对应操作授权后执行。不要通过重复发送未知结果的请求来验证重试，也不要通过删除真实待确认记录、强杀桌宠或更改系统时间制造“恢复成功”。

真实验证记录包含构建与桌宠版本、触发步骤、本地和服务器结果，以及未确认记录的状态。分别列出只读探测和实际写入操作，日志去除账号标识等敏感信息。

### 领取期间的累计计数恢复缺口

桌宠 1.0.5 的领取动作会把本地点击增量并入内存累计值并清零增量，旧助手在领取时也调用了这个动作并强制保存清零后的增量。若服务器与账号累计缓存尚未包含这批点击，桌宠在此时突然中断，启动恢复可能少计。用原版启动、登录和计数加载逻辑，配合隔离磁盘与模拟服务器，已复现内存累计 `3015`、重启后恢复为 `3000`。若服务器或同账号累计缓存已有 `3015`，启动可恢复为 `3015`。单独先写累计缓存也有风险：旧增量 `15` 尚留在磁盘、服务器已追平到 `3015` 时，启动会得到 `3030`。

当前[助手领取链路](../src/Bridge/claim.js)以服务器累计值提交，成功后只更新本地消费，保留本地增量及桌宠自身保存与上报流程。隔离测试覆盖账户余额未同步、上报与领取交错和页面丢失后不重发。原版桌宠自己的领取、上报与重启流程仍可能触发计数缺口。隔离验证没有证明真实账号已丢失点击。

### 使用服务器累计值领取的契约验证

国服桌宠 1.0.5 曾在独立验证中接受一次不含本地增量的 `click_num`。后续查询确认消费增加 `1000`，仅目标槽位进入冷却，对应奖励增加 `1`。原版自然上报早于领取后的独立查询结果，无法确认最初保留的增量是否恰好计入一次。这笔验证支持请求参数的选择，不等同于当前构建的完整真实验证。

范围限于一个明确授权的账号、一个已到期的槽位、一次领取请求和一次原版计数上报。领取可能消耗宝箱机会和 1000 次可用次数，上报会修改账号累计值。执行前须取得用户对这两项真实写入的明确授权；准备方案、读取日志或以往授权不代表本次已获准。

1. **记录基线。** 确认服务器累计 `S` 减去已消费 `C` 至少为 `1000`，本地已有一笔可区分的未上报增量 `D > 0`。记录两个槽位冷却、已消费次数、累计值和背包数量。选用没有其他领取、奖励发放、点击或计数上报交错的观察窗口；无法建立稳定基线则不发请求。
2. **验证领取。** 只发一笔指定槽位的领取，请求使用 `click_num=S`。保留原本的 `D`，不调用会合并并清零它的本地动作。核对该请求的业务回执，等只读查询显示累计仍为 `S`、消费为 `C+1000`、仅目标槽位进入新冷却，且回执对应的奖励在背包中增加。只收到成功回执不足以通过本阶段。
3. **验证保留点击可以后续上报。** 在领取结果已读到、增量仍为 `D` 的情况下，观察一次已授权的原版上报，核对其累计参数为 `S+D`。等查询显示累计恰为 `S+D`，消费仍为 `C+1000`、两槽冷却与领取后一致、奖励增量保持不变。三个阶段的数据都对得上才记为通过。

如果领取超时或结果未知，保留记录，只做只读核对，不重发，也不继续上报。明确拒绝时记录业务码并结束。若未观察到分开的领取后状态、出现额外输入或上报、同物品的其他发放、账号变化或限流，记录为未能判定，另外报告已发生的实际写入。日志只保存版本、时序、脱敏计数差值和结果。一次通过只说明该版本与该测试条件下的顺序行为，不覆盖并发上报或异常重启。
