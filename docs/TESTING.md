# 测试与验证

使用方法见 [README](../README.md)，构建和内部约束见 [DEVELOPMENT](DEVELOPMENT.md)。本页区分自动测试、真实桌宠只读探测和真实账号操作；三者不能相互替代。

## 自动测试命令

从仓库根目录执行，环境要求见[开发文档](DEVELOPMENT.md)。原生检查在 Windows 上运行：

```powershell
.\scripts\Build.ps1 -Test
```

命令编译助手和 `Tests.exe`，并运行原生检查，输出位置遵循开发文档中的本地构建规则。测试会使用临时文件、模拟客户端、WPF 窗口与子进程、回环 WebSocket，但不操作真实账号、不重启桌宠、不修改系统启动配置。

桥接脚本测试需要 Node.js：

```powershell
node tests/discovery.cjs
node tests/boost.cjs
node tests/claim.cjs
node tests/state.cjs
```

这些命令使用模拟模块、store、时钟和请求，不连接真实桌宠。CI 执行同一组原生和 JS 检查；本地通过不代表当前远程 CI 已通过。

## 程序检查入口

仅检查嵌入资源，不连接桌宠：

```powershell
& .\build\0.1.5.1\WuwaTappoHelper.exe --check
```

对已运行且可连接的桌宠进行只读探测：

```powershell
$probePath=Join-Path (Get-Location) 'build\0.1.5.1\probe.json'
& .\build\0.1.5.1\WuwaTappoHelper.exe --probe $probePath
```

以上路径仅为示例，请换成待测构建及本机输出绝对路径。`--probe` 会创建助手目录下的 `runtime/`，并写入指定探测文件；失败也可能写启动诊断。它读取真实桌宠接口、校验本地状态和服务器宝箱时间，不执行补数、领取或桌宠重启，也不会为普通启动的桌宠自动开启调试会话。`--check` 或 `--probe` 成功均不能替代真实领取验证。

预览生成及其模拟数据隔离方式见[开发文档](DEVELOPMENT.md)。预览复用 WPF 渲染，不能证明真实账号操作成功。

## 尚未完成的真实环境验证

以下场景即使存在模拟覆盖，仍不可描述为已经完成真实验证：

- 当前直接接口领取的完整流程：消费回执、本地扣数及保存、服务器冷却、两个宝箱串行领取。
- 首次管理员启动、取消权限提示或启动失败后的完整恢复。
- 真实断线重连、首次连接失败后恢复；补数或领取请求途中断线、慢响应、服务器错误、限流及保存失败后的恢复。
- 旧计数上报覆盖补数，以及观察超时后迟到回执的真实时序。
- 桌宠运行期间更新、页面重载或重启，包含能力重新发现、回执丢失和未确认记录的处理。
- 换账号、手动领取或其他计数变化时，确保不会错误确认原操作、重复补数或重复领取。
- 锁屏后持续运行、休眠期间停止执行及唤醒后的完整恢复；不要据此推断原桌宠如何计算活跃时长。
- “停止并恢复桌宠”的完整流程，包括调试配置恢复失败、桌宠未正常退出时的用户处理。

真实操作会影响账号次数与宝箱状态，应在获得对应操作授权后执行。不要通过重复发送未知结果的请求来验证重试，也不要通过删除真实待确认记录、强杀桌宠或更改系统时间制造“恢复成功”。

记录真实验证时，至少注明构建、桌宠版本、触发步骤、观察到的本地／服务器结果，以及是否存在未确认记录。分别列出只读探测和实际写入操作；日志应去除原始账号标识等敏感信息。无法确认时保持“未验证”，不要用源码存在某条处理路径代替运行证据。
