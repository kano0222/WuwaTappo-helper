# 测试与验证

使用方法见 [README](../README.md)，构建和内部约束见 [DEVELOPMENT](DEVELOPMENT.md)。本页区分自动测试、真实桌宠只读探测和真实账号操作；三者不能相互替代。

## 按改动范围检查

从仓库根目录执行；原生测试需要 Windows/.NET Framework，桥接测试需要 Node.js，环境见[开发文档](DEVELOPMENT.md)。日常修改只运行受影响的组，跨层修改运行相关各组；提交或发布前运行一次全量，不必在每次小改后重复全量。

| 改动范围 | 命令 | 覆盖 |
| --- | --- | --- |
| 策略、Worker、连接、恢复、状态文件、能力校验 | `./scripts/Test.ps1 -Suite Worker` | 策略边界、待确认记录、服务器确认、退避与手动重试、断线恢复、版本映射。 |
| WPF 面板、托盘、关闭、反馈及更新交互 | `./scripts/Test.ps1 -Suite Panel` | 布局、按钮指令、提示优先级、暂停、隐藏／唤起／退出及更新交互；会打开隔离测试窗口。 |
| 启动参数、WebSocket、更新请求 | `./scripts/Test.ps1 -Suite Platform` | 子进程参数保留、回环连接释放、版本比较、HTTP 错误和取消。 |
| 所有桥接脚本 | `./scripts/Test.ps1 -Suite Bridge` | 资源发现、补数、领取及状态查询。 |
| 单个桥接脚本 | `./scripts/Test.ps1 -Suite Boost` | 可选 `Discovery`、`Boost`、`Claim`、`State`。 |
| 全量回归 | `./scripts/Test.ps1` | 全部原生与四组 JS 测试。 |

例如改动 `boost.js` 只跑 `Boost`；同时改动 Worker 的补数处理，再跑 `Worker`。修改共享 `state.js` 或桥接能力契约时跑 `Bridge` 和 `Worker`；共享数据模型或跨模块重构跑全量。纯文档修改只核对内容和链接，无需构建、探测真实桌宠或生成预览。

原有 `./scripts/Build.ps1 -Test` 仍运行全部原生测试，CI 保持全量检查。原生测试使用临时文件、模拟客户端、WPF 窗口与子进程和回环 WebSocket；JS 使用模拟模块、store、时钟及请求。均不操作真实账号、不重启桌宠、不修改系统启动配置。本地通过不代表当前远程 CI 已通过。

关键回归保留：补数保存挂起不重叠写入、退避后仅恢复保存、真实输入及新旧上报竞争；领取必须同时有消费和奖励背包增量证据，查询失败或迟到不能误报成功，刷新失败不得重发领取。模拟测试不能证明真实到账、持久化或桌宠私有冷却及动画同步。

## 程序检查入口

仅检查嵌入资源，不连接桌宠：

```powershell
& .\build\0.1.5.1\WuwaTappoHelper.exe --check
```

对已运行且可连接的桌宠进行只读探测：

```powershell
$probePath=Join-Path (Get-Location) 'build\0.1.5.1\probe.json'
& .\build\0.1.5.1\WuwaTappoHelper.exe --probe $probePath
```

以上路径仅为示例，请换成待测构建及本机输出绝对路径。`--probe` 会创建助手目录下的 `runtime/`，并写入指定探测文件；失败也可能写启动诊断。它读取真实桌宠接口、校验本地状态和服务器宝箱时间，不执行补数、领取或桌宠重启，也不会为普通启动的桌宠自动开启调试会话。`--check` 或 `--probe` 成功均不能替代真实领取验证。

预览生成及其模拟数据隔离方式见[开发文档](DEVELOPMENT.md)。预览复用 WPF 渲染，不能证明真实账号操作成功。

## 真实环境验证边界

历史构建的检查数量和逐轮执行记录不作为日常检查清单。按本次改动报告执行命令、结果和未验证项，不要求为增加检查数量而重复相同断言。

以下场景即使存在模拟覆盖，仍不可描述为已经完成真实验证：

- 当前直接接口领取的完整流程：消费回执、本地扣数及保存、服务器冷却、两个宝箱串行领取。
- 首次管理员启动、取消权限提示或启动失败后的完整恢复。
- 真实断线重连、首次连接失败后恢复；补数或领取请求途中断线、慢响应、服务器错误、限流及保存失败后的恢复。
- 旧计数上报覆盖补数，以及观察超时后迟到回执的真实时序。
- 桌宠运行期间更新、页面重载或重启，包含能力重新发现、回执丢失和未确认记录的处理。
- 换账号、手动领取或其他计数变化时，确保不会错误确认原操作、重复补数或重复领取。
- 锁屏后持续运行、休眠期间停止执行及唤醒后的完整恢复；不要据此推断原桌宠如何计算活跃时长。
- “停止并恢复桌宠”的完整流程，包括调试配置恢复失败、桌宠未正常退出时的用户处理。

真实操作会影响账号次数与宝箱状态，应在获得对应操作授权后执行。不要通过重复发送未知结果的请求来验证重试，也不要通过删除真实待确认记录、强杀桌宠或更改系统时间制造“恢复成功”。

记录真实验证时，至少注明构建、桌宠版本、触发步骤、观察到的本地／服务器结果，以及是否存在未确认记录。分别列出只读探测和实际写入操作；日志应去除原始账号标识等敏感信息。无法确认时保持“未验证”，不要用源码存在某条处理路径代替运行证据。
