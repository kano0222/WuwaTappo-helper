# 测试与验收

## 选择验证

从用户或调用方能观察到的结果确定验收入口。修改共享判断、恢复或回退路径时，回查原修复分别允许和拒绝哪些操作，把仍适用的条件带入本次验收。可隔离复现的故障优先在修复前后验证同一场景。

从仓库根目录运行 `.\scripts\Test.ps1 -Suite <组名>`。原生组使用 Windows/.NET Framework，桥接组使用 Node.js。[测试脚本](../scripts/Test.ps1)

| 改动 | 验证选择 |
| --- | --- |
| 调度、确认与恢复 | `Worker` |
| 面板、托盘、窗口交互 | `Panel`（会打开隔离的 WPF 窗口） |
| 进程归属、端口、传输、更新包 | `Platform` |
| 页面桥接 | `Bridge` 或受影响的 `Discovery`、`Boost`、`Claim`、`Pair`、`State` |
| 重要共享契约、影响难以界定的改动、发布候选 | `.\scripts\Test.ps1` 全量回归，并复核本次交付的关键场景 |

局部提交按影响选组；跨层改动还要从实际调用入口验证衔接，例如双箱请求应从原生入口成功组装内嵌脚本并到达传输层。纯文档改动核对内容、链接及所述行为即可。

## 关键回归场景

| 触发条件 | 验收结果 |
| --- | --- |
| 遗留原生后台记录，PID 被复用或进程身份查询受限 | 锁已释放时可以重新启动；锁仍被持有时阻止重复启动。即使持锁，也拒绝向已确认过期的会话或身份不完整的原生记录发送控制命令，新会话忽略旧命令。[后台归属检查](../tests/Tests.cs) |
| 合法 WebView2 由 Explorer 拉起，或系统只能提供部分端口证据 | 参数可用时，监听记录漏报仍可用实际 TCP 连接核实归属；参数不可用时，仅接受唯一、已核实归属的主窗口。参数歧义、进程退出或另一实例的监听均不能放行。[宿主](../tests/HostedWebViews.cs) · [端口](../tests/Endpoints.cs) |
| 宝箱成功回执早于账号查询，或请求完成前后断线 | 双箱按各自回执推进；最终能将扣数、槽位和奖励对应到原操作。核验期间保留回执时间与待确认记录，恢复不重发；桌宠原有的未上报点击仍可继续上报。[双箱](../tests/pair.cjs) · [恢复](../tests/Recovery.cs) |
| 手动暂停、服务器限流或补数保存失败后重试 | 人工停止意图和强制等待继续生效；恢复保存不会再增加一次计数。[退避与重试](../tests/Retry.cs) · [补数保存](../tests/boost.cjs) |

## 程序检查入口

在待测构建目录运行：

```powershell
.\WuwaTappoHelper.exe --check
.\WuwaTappoHelper.exe --probe "$PWD\probe.json"
```

`--check` 校验内嵌资源。`--probe` 需要该实例已配置桌宠路径，且桌宠正在运行、调试入口已可连接。它读取真实页面能力、本地状态及服务器宝箱时间，创建本地运行目录并写探测结果，不补数或领取。探测额外实例时在末尾加 `--instance <id>`，取值见 `runtime/instances/`。[程序入口](../src/Program.cs)

## 需要现场判断的结果

隔离测试可控制时序，真实界面与服务器到账需分别取证。涉及相应改动时，重点关注以下缺口：

- **系统与窗口。** 监听记录漏报在故障机器上的表现、多实例经过休眠后的恢复，需用对应环境核实。检查焦点问题时，在完整和 Mini 窗口分别实际切换 Alt+Tab，区分焦点移动与仅出现描边。
- **账号与冷却。** 助手能核对双箱到账，原桌宠按钮随左右回执分别更新的精确时序仍需现场观察；切号或上报与领取交错时，应分别核对账号、次数和奖励。仅在授权覆盖具体账号写入时执行真实操作。

报告时注明待测构建、桌宠版本、触发条件和实际观察，区分只读探测与真实写入。历史测量与排查经过可追溯至相应提交、Issue 或 PR。
