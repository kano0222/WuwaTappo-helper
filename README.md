# Wuwa Tappo Helper

Windows 上的 Wuwa Tappo 后台助手。提供可视化控制台，集中查看次数、宝箱进度与最近活动，并管理启动、暂停、继续和停止。

这是第三方工具，与库洛无隶属关系。不包含桌宠程序、解包资源或账号存档。

## 环境

- Windows 64 位。打包后的目录已随附 PowerShell 7 和 Node.js，无需单独安装。
- 已安装并登录 Wuwa Tappo。1.0.0、1.0.1 为已核对版本。
- 启动时自动发现当前加载的应用资源，校验环境、状态字段、只读接口、补数事件、宝箱入口和正常退出能力。版本号、文件哈希和导出缩写变化不会单独导致拒绝；未知版本满足现有契约即可接入。接口缺失、含义无法确认或候选不唯一时会停止并提示兼容性检查失败，不尝试补数或领取。

项目使用系统组件和 Node.js 内置模块，无需安装 npm 依赖。从源码构建时，需要 Node.js 22 或更新版本、PowerShell 7。

## 配置与使用

1. 解压完整分发包到可写目录，双击 **WuwaTappoHelper.exe**。请保留同目录的 `dependencies/`、脚本和资源，不要单独移动 exe。打开面板本身不会启动自动化，也不会出现命令窗口。
2. 助手会优先读取已保存路径，再检查运行中的桌宠、安装记录及常见安装位置，不扫描全部磁盘。找不到安装位置时，点击 **选择程序** 指定一次 `WuwaTappo.exe`，或者点击启动时按提示选择；以后自动记住。不需要编辑配置文件。
3. 先在原桌宠登录。如果它已普通启动，请从设置或托盘选择“退出应用”，再点面板的 **启动后台**。按需处理 Windows 管理员提示。
4. 使用 **暂停 / 继续运行** 控制自动操作。**停止并恢复桌宠** 会正常退出调试实例并恢复桌宠普通启动。
5. 在 **次数增加模式** 中点击模式卡片即可保存，后台会在下一轮检查时应用。模式保存在本机 `runtime/preferences.json`；旧后台需正常停止并重新启动。未启动时只保存选择，暂停时不会恢复运行。

右上角关闭（包括 Alt+F4）会把面板收进系统托盘，后台状态不变。托盘图标显示后台状态，双击可打开面板；右键可暂停／继续、停止并恢复普通桌宠，或 **停止自动化并退出助手**。退出只等待自动化停止并断开连接，不启动或关闭桌宠；未确认停止时保留助手并提示处理。桌宠的本机调试入口会保留到桌宠退出；如需关闭入口并继续使用桌宠，请选择独立的“停止并恢复普通桌宠”。未运行自动化时，托盘菜单可直接退出助手。Windows 可能把托盘图标放在右下角的折叠菜单中。

面板每秒刷新；后台停止、离线或状态过期时，会明确标注上次记录，避免把旧数据当作实时状态。“本次运行领取”从本次后台启动计数，暂停或隐藏面板不清零，重新启动后台才清零。

宝箱倒计时读取原程序用户信息接口返回的左右槽位冷却结束时间，启动后台后首次查询，之后每 30 秒同步，界面每秒本地倒计时。暂停或有未确认记录时仍会只读同步；领取前后的服务端查询也会更新显示。查询失败或时间超过 90 秒未更新时显示“等待同步”，不退回桌宠缓存冒充最新结果。宝箱是否显示、次数是否达到 1000 不影响时间查询；实际领取仍须满足原按钮及服务端校验条件。

同一 Windows 用户重复打开时会唤起已有面板；不同用户的面板互不占用单实例锁。窗口显示、关闭及清理记录保存在 `runtime/panel-lifecycle.log`。

缺少文件或启动失败时会显示原因，并写入 `runtime/panel-launcher-error.log`。

`config.local.json` 只存放本机安装路径，已排除版本控制。不要填写账号密码或登录令牌。

## 自动化行为

- 每秒检查状态，不发送系统鼠标键盘输入，不切换前台窗口。
- 储备目标为 2000 次，可供两个宝箱各消耗 1000 次。暴力模式：宝箱到期且余额不足以领取时，一次补足至 2000。连点器、人类模式：后台运行且余额不足 2000 时提前累积，无需等待宝箱到期；达到 2000 后停止增加，领取消耗后继续补充。
- 连点器模式每批最多 100 次，批次间隔约 1 秒，近似 10ms/次的平均速率，但不是逐次点击。人类模式每批 2–7 次，间隔 1–1.5 秒，偶尔间歇 2–4 秒。最后一批均以差额为限；网络等待会降低实际速率，不会补发积压批次。
- 三种模式都调用同一内部事件；“人类模式”只是波动速率，不代表真实人工输入或获得反检测保障。批量增加减少调用与状态保存开销，并不意味着逐次定时器会无限占用内存。
- 宝箱到期且原按钮可用时，复用应用原有领取逻辑；两个槽位串行处理。
- 领取前后查询服务器，核对恰好扣除 1000 次、指定槽位进入下一轮、另一个槽位未被改变，并等待领取动画结束，再处理下一个宝箱。结果不确定时保留记录并暂停，不自动重试。
- 原程序明确返回“冷却中”等业务拒绝时，会再次核对服务器是否扣数或改变槽位；只有确认没有变化才结束本次待确认记录，并暂停等待处理。网络超时、未知错误或状态变化不一致仍保留记录，不自动重发。
- 不修改系统时间、冷却或活跃时长。闲置、锁屏及休眠是否计为活跃，仍取决于原软件，不保证这些情况下继续产箱。
- 登录失效、更新锁或结果不确定时暂停；不会自动重复发送不确定的操作。

启动时临时配置只针对 WuwaTappo.exe，就绪后立即恢复。运行期间调试端口 19222 只监听本机；暂停保留连接，停止并正常退出调试实例后才关闭端口。没有开机启动或定时任务。

首次接入普通运行的桌宠需要重启一次，以启用本地连接。“停止并恢复桌宠”会结束该连接并重启为普通桌宠，因此下次启动助手需要重新接入。日常临时停用请使用“暂停／继续”，无需重启；切换模式也无需重启。若只结束自动化进程而保留桌宠，连接入口仍可能存在；若连桌宠也关闭，则桌宠停止运行，不会继续计算活跃时间。

## 状态与故障

`runtime/` 在使用时自动生成，包含状态、日志和操作确认记录，已排除版本控制。运行期间不要删除这个目录。

存在 `runtime/pending.json` 表示上次操作的结果尚未确认，此时禁止直接继续。请查看面板提示和日志，正常停止并核对桌宠；不要直接删掉记录后重试。

如果电脑或脚本异常退出，请手动退出桌宠以关闭调试入口，再核对未确认记录。工具不会强制结束桌宠。

```text
lib/                         应用连接、状态保存、本机配置读取

app-profile.json             已核对发行版本的参考信息（非版本白名单）

dependencies/                构建时生成的随附运行环境及其许可证
```

## 构建 exe

在项目根目录通过 PowerShell 7 执行：

```powershell
.\scripts\Build-Launcher.ps1
```

构建脚本使用 Windows 自带的 .NET Framework 编译器生成无控制台启动器，复制当前 PowerShell 7 和 Node.js，并从 Node.js 官方仓库获取对应版本的许可证。也可用 `-PowerShellHome`、`-NodePath` 和 `-NodeLicensePath` 指定构建来源或离线许可证。首次构建需要联网获取许可证；运行时无需联网下载依赖。

`WuwaTappoHelper.exe` 和 `dependencies/` 是生成文件，已排除版本控制。分发完整目录时须包含它们，并保留随附的第三方许可证；不要包含本机配置、运行记录或桌宠安装文件。启动器仅对自己启动的 PowerShell 进程设置执行策略，不修改系统全局策略。

## 获取分发包

推送到 `main` 后，GitHub Actions 的 **Build Windows helper** 工作流会自动运行测试、构建 Windows 分发包并检查启动器。也可在 Actions 页面手动运行。成功后在对应运行页面的 **Artifacts** 下载 `WuwaTappoHelper-win-x64-运行编号`，产物保留 30 天。

分发包由 GitHub 的 Windows 构建环境调用 `scripts/Build-Distribution.ps1` 生成，无需在本机打包。包内包含 exe、随附 PowerShell / Node.js、必要脚本、图标及第三方许可证；通过文件白名单排除本机配置、账号运行记录、网络诊断文件及测试材料。使用者仍须自行安装并登录接口兼容的桌宠，并处理管理员提示。首次找不到安装位置时，选一次程序即可。
