# Wuwa Tappo Helper

Windows 上的 Wuwa Tappo 后台助手，提供次数统计、宝箱倒计时、三种增加模式、最近活动和系统托盘控制。

![真实 WPF 面板动态预览：次数增长、宝箱倒计时、模式切换和暂停／继续](docs/images/readme-motion.png)

预览使用模拟数据，不连接桌宠或账号。

第三方工具，与库洛无隶属关系。不包含桌宠程序、桌宠资源或账号存档。

## 环境与启动

- Windows 10 22H2 / Windows 11，64 位，使用系统预装的 .NET Framework 4.8 或兼容更新。
- 自行安装并登录 Wuwa Tappo，助手连接时会检查接口兼容性。
- 从 [Releases](https://github.com/kano0222/ww-tappo/releases) 下载完整分发包，解压到当前用户具有写入权限的目录，避免放入 `Program Files` 等受保护目录。
- 双击 `WuwaTappoHelper.exe`，无需安装 PowerShell 7、Node.js 或 Python。

助手启动时及每 6 小时自动检查 GitHub 正式版本，也可点击底栏的版本按钮手动检查。发现新版后点击提示打开发布页；检查失败会在 15 分钟后重试，不影响后台运行。更新时请完全退出助手并保留配置与 `runtime/`，程序不会自动下载或覆盖文件。

打开面板后点击“启动后台”。助手会自动查找桌宠，也可点击“选择程序”指定 `WuwaTappo.exe`。

首次启用前，如果桌宠已普通启动，请从桌宠设置或托盘选择“退出应用”，再点击“启动后台”，并按需允许 Windows 管理员提示。面板本身不要求管理员权限。

## 控制行为

- **暂停 / 继续**：暂停或恢复自动操作，不重启桌宠。暂停期间仍可只读同步宝箱时间。
- **查询失败自动重试**：操作前的只读状态查询失败时，按 5、10、20、40、60 秒退避，之后每隔 60 秒重试；等待期间不补数、不领取，恢复后继续，手动暂停仍保持有效。操作已提交但结果未确认时仍暂停，不自动重发。
- **结束待确认操作**：出现未确认记录时显示。确认后将原记录及处理说明归档到 `runtime/history/`，不重发原操作；已连接的后台恢复自动化，未运行时需手动启动。不会清零次数、宝箱进度或日志。
- **停止并恢复桌宠**：请求桌宠正常退出，再以普通方式启动，以关闭本机调试入口。不强制结束桌宠。
- **关闭面板**：点击右上角“×”后，可选择“退出”或“最小化到托盘”；关闭提示框的“×”或按 Esc 取消操作。最小化到托盘后后台继续运行，双击托盘图标或再次打开 exe 可唤起面板。
- **退出助手**：点击右上角“×”后选择“退出”，或右键面板空白处／系统托盘图标选择退出。等待当前处理结束，停止自动化并断开连接，不启动或关闭桌宠。本机调试入口保留到桌宠退出。

连接断开时会尝试重新连接现有桌宠，不会自动重启桌宠。首次连接会等待主窗口就绪，启动失败时面板显示具体原因。

若确认补数被旧计数上报覆盖，会记录结果并按最新计数继续；结果不明时仍暂停，不自动重发。

同一目录、同一 Windows 用户只运行一个面板和后台。请勿同时从多个目录启动助手。

## 次数和宝箱

储备目标为 2,000 次，每箱消耗 1,000 次。三种模式选择即保存，运行中的后台会在下一轮读取并应用。

- **暴力模式**：原宝箱入口到期可用、余额不足目标时，一次补足。
- **连点器模式**：提前累积，每批最多 100 次，约每秒一批。
- **人类模式**：提前累积，模拟不规则点击间隔；通常每批 2–7 次，间隔 1–1.5 秒，偶尔间歇 2–4 秒。

宝箱时间来自桌宠用户信息接口，每 30 秒同步，面板每秒更新倒计时；查询失败或超过 90 秒未更新时显示“等待同步”。查询不要求余额达到 1,000，进度条按 30 分钟范围换算，不代表点击次数。

领取复用桌宠原按钮，两个宝箱依次处理。每次核对服务器扣除 1,000 次、对应宝箱进入下一轮、另一宝箱不变，并等待动画结束。超时、未知错误或结果不一致时暂停，保留记录供核对。

暴力模式依赖原领取入口可见，余额不足 1,000 时可能持续等待；连点器和人类模式会提前累积次数。

不会修改系统时间、冷却或活跃时长。锁屏、闲置、休眠是否计入活跃时间取决于原桌宠。

## 本机文件与升级

配置与记录保存在助手所在目录中：

- `config.local.json`：桌宠路径。
- `runtime/preferences.json`：所选模式。
- `runtime/events.jsonl`：本地活动日志，面板显示最近三条；日志持续追加，暂无自动轮转。
- `runtime/status.json`：后台状态与接口宝箱时间。
- `runtime/pending.json`：未确认操作；`runtime/history/`：手动结束操作时保留的原记录与处理说明。
- `runtime/panel-lifecycle.log`、`runtime/panel-launcher-error.log`：窗口和启动诊断日志。
- `runtime/debug-policy-session.json`：临时调试启动配置与恢复结果。

有未确认记录时，先核对桌宠，再使用“结束待确认操作”归档，不要直接删除记录后重试。删除 `runtime/` 会丢失模式设置、日志和恢复记录，不能撤销已执行的操作。

升级时完全退出助手及后台，替换 `WuwaTappoHelper.exe` 和 `WuwaTappoHelper.exe.config`，保留 `config.local.json` 与整个 `runtime/`。

启动时临时设置桌宠的 WebView2 调试配置，连接就绪后恢复原值。调试端口 `19222` 必须仅监听本机。助手不设置开机启动或定时任务。

## 构建与检查

在 Windows 上使用系统自带的 .NET Framework C# 编译器构建并运行原生检查：

```powershell
.\scripts\Build.ps1 -Test
```

产物位于 `build/`，标签构建使用对应版本号；源码构建可用 `-Version X.Y.Z` 指定版本。桥接脚本测试另需开发环境中的 Node.js：

```powershell
node tests/discovery.cjs
node tests/boost.cjs
```

原生检查覆盖模拟策略、异常恢复、WPF 窗口隐藏／唤起／退出，以及回环 WebSocket 断线；JS 测试覆盖资源发现和补数回执。自动测试不操作真实账号或系统启动配置。程序的 `--check` 参数仅检查嵌入资源，不能替代真实桌宠验证；`--probe 输出文件.json` 只读检查已运行桌宠的接口。

GitHub Actions 完成上述检查后生成压缩包：`main` 推送和手动构建上传 **Artifacts**，保留 30 天；推送 `v*` 标签还会创建 **GitHub Release** 并附上分发包。Artifacts 不等同于 Release。

仓库与分发包不包含本机配置、运行记录、桌宠安装文件或账号数据。

### 重新生成 README 预览

在 Windows 上安装开发工具 FFmpeg 后执行：

```powershell
.\scripts\Generate-ReadmePreview.ps1
# FFmpeg 不在 PATH 时：
.\scripts\Generate-ReadmePreview.ps1 -FFmpeg 'C:\tools\ffmpeg\bin\ffmpeg.exe'
```

脚本复用真实 `Panel.xaml` 和 `Panel.Render()`，通过 `--render-preview 帧输出目录` 生成模拟帧，再编码为 11 秒无限循环的 APNG。生成入口跳过桌宠查找、连接、托盘及更新检查，模拟数据仅写入临时目录并在结束后清理，不读取或修改真实 `runtime/`。构建和中间帧位于 `build/readme-preview/`，最终图片位于 `docs/images/readme-motion.png`。正常构建与发布不会自动生成预览，FFmpeg 也不是助手的运行依赖。
