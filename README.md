# Wuwa Tappo Helper

Windows 上的 Wuwa Tappo 后台助手，提供次数统计、宝箱倒计时、三种增加模式、最近活动和系统托盘控制。

第三方工具，与库洛无隶属关系。不包含桌宠程序、桌宠资源或账号存档。

## 环境与启动

- Windows 10 22H2 / Windows 11，64 位，使用系统预装的 .NET Framework 4.8 或兼容更新。
- 自行安装并登录 Wuwa Tappo。1.0.0 / 1.0.1 是已核对的接口版本；未知版本按资源和能力校验，不按版本号或文件哈希阻止使用。
- 解压完整分发包，双击 `WuwaTappoHelper.exe`。无需安装 PowerShell 7、Node.js 或 Python。

打开面板不会自动运行后台。助手会读取保存的安装路径，并检查运行进程、安装记录和常见安装位置；也可点击“选择程序”指定 `WuwaTappo.exe`。

首次启用前，如果桌宠已普通启动，请从桌宠设置或托盘选择“退出应用”，再点击“启动后台”，并按需允许 Windows 管理员提示。面板本身不要求管理员权限。

## 控制行为

- **暂停 / 继续**：暂停或恢复自动操作，不重启桌宠。暂停期间仍可只读同步宝箱时间。
- **查询失败自动重试**：操作前的只读状态查询失败时，按 5、10、20、40、60 秒退避，之后每隔 60 秒重试；等待期间不补数、不领取，恢复后继续，手动暂停仍保持有效。操作已提交但结果未确认时仍暂停，不自动重发。
- **结束待确认操作**：出现未确认记录时显示。确认后将原记录及处理说明归档到 `runtime/history/`，不重发原操作；已连接的后台恢复自动化，未运行时需手动启动。不会清零次数、宝箱进度或日志。
- **停止并恢复桌宠**：请求桌宠正常退出，再以普通方式启动，以关闭本机调试入口。不强制结束桌宠。
- **关闭面板**：隐藏到系统托盘，后台状态不变。双击托盘图标或再次打开 exe 可唤起面板。
- **退出助手**：点击标题栏“退出助手”，或右键面板空白处／系统托盘图标选择退出。等待当前处理结束，停止自动化并断开连接，不启动或关闭桌宠。本机调试入口保留到桌宠退出。

同一目录、同一 Windows 用户只保留一个面板和一个后台。不同用户的面板使用独立窗口锁。旧后台尚未停止时，新后台会拒绝重复启动。

## 次数和宝箱

储备目标为 2,000 次，每箱消耗 1,000 次。三种模式选择即保存，运行中的后台会在下一轮读取并应用。

- **暴力模式**：原宝箱入口到期可用、余额不足目标时，一次补足。
- **连点器模式**：提前累积，每批最多 100 次，约每秒一批。
- **人类模式**：提前累积，每批 2–7 次，间隔 1–1.5 秒，偶尔间歇 2–4 秒。仅为波动速率，不代表真实人工输入。

宝箱时间来自原程序用户信息接口。首次连接查询，之后每 30 秒同步，面板每秒本地倒计时；查询失败或超过 90 秒未更新时显示“等待同步”。时间查询不要求余额达到 1,000。进度条仍沿用 30 分钟范围换算，不代表点击次数。

实际领取复用桌宠原按钮。两个槽位串行处理，领取前后核对服务器恰好扣除 1,000 次、对应槽位进入下一轮、另一槽位不变，并等待动画结束。明确业务拒绝且服务器状态未变才清理本次记录；超时、未知错误或确认不一致时暂停，不自动重发。

暴力模式仍依赖原领取入口可见，余额低于 1,000 导致入口隐藏时可能等待；本次语言迁移保留该既有行为。连点器、人类模式会提前累积。

不会修改系统时间、冷却或活跃时长。锁屏、闲置、休眠是否计入活跃时间取决于原桌宠。

## 本机文件和旧版升级

配置与记录保存在助手所在目录中：

- `config.local.json`：桌宠路径。
- `runtime/preferences.json`：所选模式。
- `runtime/events.jsonl`：持续追加的本地活动记录，面板最多显示最近三条；目前没有自动轮转。
- `runtime/status.json`：后台状态与接口宝箱时间。
- `runtime/pending.json`：结果尚未确认的操作记录。存在时阻止自动操作与继续运行；核对后可使用“结束待确认操作”归档，不要手动删除后重试。
- `runtime/panel-lifecycle.log`、`runtime/panel-launcher-error.log`：窗口生命周期和启动错误。
- `runtime/debug-policy-session.json`：临时调试启动配置与恢复结果。

从旧版升级时，先退出旧助手及其后台，再将新 exe 和 exe.config 放回原目录，保留原有配置与整个 `runtime/`。新版本直接读取原文件格式，不自动删除或重试旧的未确认记录。旧目录中的 `dependencies/` 和旧脚本不再被新 exe 使用。

启动连接时会临时设置仅针对 WuwaTappo.exe 的 WebView2 调试配置，就绪后恢复原值。调试端口 19222 必须只监听本机。程序没有开机启动或定时任务。

## 自动构建与开发检查

推送到 `main` 后，GitHub Actions 的 **Build Windows helper** 自动编译 C#、运行模拟后台和真实 WPF 生命周期检查，再生成分发包并上传到该次运行的 **Artifacts**，保留 30 天。也可手动触发。压缩包由 GitHub 工作流生成。

Artifacts 是构建产物，不等同于 GitHub Release。正式版本需先审查代码与版本号，再推送对应的 `v*` 标签；标签触发的工作流会重新测试和构建，全部通过后创建 GitHub Release，并附上 `WuwaTappoHelper-win-x64.zip`。普通 `main` 推送和手动构建不自动发布 Release，版本标签也不会由工作流擅自创建。

本地仅编译和检查：

```powershell
.\scripts\Build.ps1 -Test
```

输出在 `build/`，该目录不提交 Git。构建脚本使用 Windows 自带的 .NET Framework C# 编译器，不下载额外依赖。本地运行不依赖构建脚本。

`src/` 包含 C# 面板、托盘、启动管理、CDP 连接、策略和后台循环；XAML、图标及 `src/Bridge/` 中少量页面桥接 JavaScript 编译进 exe。桥接脚本由桌宠 WebView2 执行，不需要 Node.js。

自动测试不操作真实账号或系统启动配置。可选的 `WuwaTappoHelper.exe --probe 输出文件.json` 仅连接现有桌宠并读取接口，不启动桌宠或发送补数、领取。

## 验证边界

C# 版通过模拟场景和窗口生命周期检查，并已接入本机 1.0.1，完成左右宝箱各一次真实领取确认及人类模式补数。普通权限面板查询管理员后台和恢复命令已验证；首次管理员启动桌宠与完整停止恢复流程尚未在真实桌宠上重新验证。历史 1.0.0 的实测结果不作为 C# 版真实操作通过的证据。
